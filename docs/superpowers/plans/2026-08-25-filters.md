# Filters Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put a user's Pokémon filters in the database and give them an interface that explains itself, replacing the per-browser `localStorage` model with server-owned rules the map resolves per entity.

**Architecture:** Rules are singular rows in MySQL, grouped for display only. The server matches them per connection and puts the matched rule ids on each delta; the client resolves appearance from the rule list it already holds, which also makes the marker popup free. The filters page is a list of grouped cards, edited in a sheet over the map.

**Tech Stack:** Bun, TypeScript, Drizzle (queries) with knex (migrations), tRPC v11, TanStack Query, Zustand, react-virtuoso, shadcn/ui, Biome, `bun test`.

## Global Constraints

- Target branch `v2`. The transport plan is merged and green at **512 unit tests, 12 transport acceptance, 12 auth acceptance**.
- Runtime is Bun. Every command is `bun`, never npm or node.
- **Server and client are TypeScript with ES modules. Never CommonJS, never plain `.js`.** The one exception is knex migration files, which are `.cjs` because the knex CLI loads them that way — match the existing files in `server/src/db/migrations/`.
- **Filenames are kebab-case, React components included.**
- Prefer `interface` over `type` for object shapes. Reserve `type` for unions, mapped and conditional types, tuples, and utility-type results.
- Lint is Biome via `bun run lint`, which is currently **clean at zero warnings**. Keep it there.
- **Never run `bun run format`.** It applies unsafe fixes. Format your own files with `bunx biome format --write <paths>`.
- **Nothing imports, calls or adapts 1.x server code.** `@rm/config` and `@rm/logger` are shared packages and are fine.
- Never write the user's name into code, comments, or documentation.
- Migrations are knex: `bun run migrate:make <name>` then `bun run migrate:latest`.
- Commit messages conventional, wrapped at 72 columns, with the trailer `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.

## Task 4: Grouping

**Files:**
- Create: `app/rules/rule-grouping.ts`, `app/rules/rule-types.ts`
- Test: `app/rules/rule-grouping.test.ts`

**This is client-only, deliberately.** The server never groups: it matches singular rules and puts
their ids on the wire. Grouping exists so a list of 25 rows reads as one card, which is a display
concern. It also *has* to live here — `tsconfig.app.json` includes only `app/**` and
`tsconfig.server.json` only `server/**`, so a module under `server/src` is not importable from a
page.

**Interfaces:**
- Produces:
  ```ts
  interface RuleGroup {
    id: string          // stable: the lowest rule id in the group, as a string
    name: string
    ruleIds: number[]
    speciesIds: (number | null)[]
    sample: Rule        // any member; they are identical except for species
  }
  function groupRules(rules: Rule[]): RuleGroup[]
  ```

`Rule` is defined in `app/rules/rule-types.ts` and is the client's view of a row as `rules.list`
returns it. The server has its own Drizzle-inferred types; the wire is the contract between them,
not a shared TypeScript interface.

export function resolveAppearance(matched: number[], rules: Map<number, Rule>) {
  const hit = matched.map((id) => rules.get(id)).filter(Boolean) as Rule[]

**Where the picker's data comes from, settled rather than assumed.**

*Structure* — which species exist and which forms each has — comes from `pogo-masterfile`, which is
**not yet a dependency; add it in this task**. Its API is a `Masterfile` class: `Masterfile.fromRemote()`
or `fromJson()`, with typed per-group accessors such as `mf.pokemonSettings.all()` and
`mf.formSettings.all()`, each carrying `.filter()`, `.find()` and `.templateIds()`. It ships
game-master template ids (`V0001_POKEMON_BULBASAUR`), not display names.

*Names* come from the translations endpoint 1.x already uses. `config/default.json` holds
`map.misc.translations` = `https://raw.githubusercontent.com/WatWowMap/pogo-translations/master`, and
`packages/locales/lib/utils.js:19` fetches `${endpoint}/static/locales/${locale}.json`. Verified
against the live file: 9,351 keys, 609 KB, of which the `poke_` and `form_` subset is about 42 KB.

```
poke_147  -> "Dratini"
poke_20   -> "Raticate"
form_46   -> "Alola"        // the form's own name, not the combined one
form_0    -> "Unset"
```

`src/features/pokemon/PokemonTile.jsx:188` composes the label as the species name plus a
parenthesised form name, so a tile reads **"Raticate (Alola)"**. Mirror that. It also means the
search term for Alolan forms is **"alola"**, not "alolan" — the design spec's example was wrong,
because `"Alola".includes("alolan")` is false.

Fetch server-side, filter to `poke_*` and `form_*`, cache in module scope, and serve the composed
list from `masterfile.species`. Do not ship the 609 KB file to the browser.
